# Card format

A card is self-sufficient: when the tmp note is gone and the session has ended, the card still answers "why, what, and why this way".

## Language

Issue language policy (issue 语言规范):

- The template (`.github/ISSUE_TEMPLATE/requirement.yml`) is bilingual (中英双语).
- Content generated by the mechanism — `pctl req new` bodies, draft comments, automation comments — is written in Chinese (中文).
- User-written content is unrestricted; we never rewrite it (不限制用户书写).

## Body

```
## 摘要
问题、要点、为什么值得做（一句到一段）。

## 验收标准
- [ ] ...   （ready 门禁要求非空）

## 决策
### YYYY-MM-DD — <topic>
- 结论: ...
- 理由: ...
- 落地: ...
```

- **Summary**（摘要）and **Acceptance criteria**（验收标准）are written by the capture fork; the user confirms.
- **Decisions**（决策）are appended only when a discussion actually concludes one (conclusion, reason, landing — the `decision.md` habit moved into the card).
- **Links**（链接）point to durable artifacts only (spec, design doc). Session links are not recorded; discussion logs are never archived.

## Draft comments

A clear idea gets a structured **draft comment** (suggested acceptance criteria, priority, effort), written in Chinese. Drafts are comments — never the committed body or labels — so a half-formed idea can't accidentally commit to structure. The card stays `idea` until the user confirms (对 / 改 / 先这样).

## Bare cards

A fuzzy idea is a one-line card: title + optional link, no forced structure. The refine stage later fills it, or the retirement stage clears it.
